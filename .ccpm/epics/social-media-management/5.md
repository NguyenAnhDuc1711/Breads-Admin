## Context

`UsersPage.tsx` hiện tự viết toàn bộ code bảng (search input, sticky header, pagination, empty-state) inline. Đây là mẫu bảng THẬT duy nhất hiện có trong `Breads-Admin` — so sánh với bản gốc `UsersCmsPage.tsx` ở `Breads-Fe` xác nhận cùng 1 pattern (search+table+pagination). Module Posts CMS (epic sau, ngoài scope) sẽ cần bảng tương tự nhưng cột khác hẳn — rút `SearchableTable` dùng chung NGAY BÂY GIỜ (dựa trên bằng chứng thật từ UsersPage) tránh việc copy-paste lặp lại 70%+ code khi Posts CMS tới, nhưng KHÔNG thiết kế props cho Posts CMS trước khi module đó tồn tại (xem AD-4 trong epic — tránh đoán sai interface).

## Description

Tạo `SearchableTable` component với props tối giản (columns, data, loading, search, pagination). Refactor `UsersPage.tsx` để dùng component này — hành vi phải giống hệt bản hiện tại, không có tính năng mới. Mở rộng `tagTypes` của `baseApi.ts` thêm `"Post"`, `"Report"` để chuẩn bị cho module tương lai dùng `injectEndpoints`.

## Implementation Steps

1. Tạo `src/components/SearchableTable/index.tsx` với props:
   ```ts
   interface Column<T> {
     key: string;
     header: string;
     render: (row: T) => React.ReactNode;
   }
   interface SearchableTableProps<T> {
     columns: Column<T>[];
     data: T[];
     loading: boolean;
     searchValue: string;
     onSearchChange: (value: string) => void;
     currentPage: number;
     totalPages: number;
     onPageChange: (page: number) => void;
     emptyMessage?: string;
   }
   ```
   Component render: search input (giống input hiện có ở `UsersPage.tsx`), `<table>` với sticky `<thead>` (copy y hệt style hiện có: `position: sticky, top: 0, zIndex: 1, backgroundColor: white`), loop `columns` để render `<th>`/`<td>` qua `render(row)`, dùng lại `PaginationBtn` (đã có ở `src/components/PaginationBtn.tsx`) cho phân trang, hiển thị `emptyMessage` khi `data.length === 0` và không `loading`.

2. Refactor `src/pages/UsersPage.tsx`: giữ nguyên toàn bộ state/hooks hiện có (`useState`, `useDebounce`, `useGetCurrentUserQuery`, `useGetUsersWithStatusQuery`, `useUpdateUserStatusMutation`). Thay phần JSX bảng bằng `<SearchableTable columns={...} data={data?.users ?? []} .../>`. Định nghĩa `columns` array với 5 cột hiện có (name, username, avatar, status, action) — mỗi cột `render` giữ nguyên JSX cell hiện tại (bao gồm `<select>` đổi status, nút "See detail").

3. Trong `src/store/api/baseApi.ts`: đổi `tagTypes: ["User"]` thành `tagTypes: ["User", "Post", "Report"]`.

4. **Xác minh bằng kiểm thử thủ công, không phải test tự động** — `package.json` của `Breads-Admin` hiện không có script/framework test nào (chỉ `dev`/`build`/`lint`/`preview`). So sánh trực tiếp hành vi trên trình duyệt: mở `UsersPage` trước và sau refactor (dùng git stash/branch để đối chiếu song song nếu cần), thao tác search/phân trang/đổi status, xác nhận giống hệt.

## Acceptance Criteria

- **FR-3 / scenario:** GIVEN `SearchableTable` đã tồn tại, WHEN `UsersPage` render, THEN dùng `SearchableTable` thay vì code bảng inline cũ (code cũ đã xoá khỏi `UsersPage.tsx`).

- **NFR-1 / scenario:** GIVEN `UsersPage` sau refactor, WHEN đổi `<select>` status của 1 user, THEN gọi đúng `useUpdateUserStatusMutation` với `userId`/`status` giống hệt logic cũ.
- **NFR-1 / scenario:** GIVEN `UsersPage` sau refactor, WHEN danh sách rỗng hoặc đang loading, THEN hiển thị đúng trạng thái tương ứng (giống bản gốc: "Loading..." / "No matching data found").
- **FR-7 / scenario:** GIVEN `baseApi.ts` sau thay đổi, WHEN 1 endpoint tương lai (ngoài scope epic này) dùng `providesTags: ["Post"]` hoặc `["Report"]`, THEN không có lỗi TypeScript.

## Technical Details

`UsersPage.tsx` hiện tại (tham chiếu để giữ hành vi):
- `ROWS_PER_PAGE = 7`, `TABLE_COLUMNS = ["name", "username", "avatar", "status", "action"]`
