## Context

`Breads-Be` hiện chỉ có `protectRoute` (xác thực JWT, gắn `req.user`) — không có middleware nào kiểm tra `role`. 7 endpoint quản trị đang chạy KHÔNG có kiểm tra quyền: `PUT /users/:id` và `GET /users/with-status` chỉ yêu cầu (hoặc thậm chí không yêu cầu) đăng nhập, không yêu cầu role Admin; `PATCH /posts/:id/status`, `PATCH /posts/:id/visibility`, `GET /reports`, `PATCH /reports/:id/response`, `PATCH /reports/:id/reject` không có bất kỳ middleware xác thực/phân quyền nào. Đây là lỗ hổng bảo mật đang tồn tại trong tính năng Users production hiện tại của `Breads-Admin` — task này vá trực tiếp lỗ hổng đó.

## Description

Tạo middleware factory `requireRole(...roles: number[])` theo đúng pattern `protectRoute.ts` (cùng thư mục `src/api/middlewares/`). Áp dụng vào đúng 7 endpoint theo bảng role-mapping dưới đây. 2 endpoint hiện thiếu CẢ `protectRoute` (post status/visibility) và 3 endpoint report (GET/response/reject) cần thêm `protectRoute` TRƯỚC `requireRole` trong chain (registration order trong Express quyết định execution order).

| Endpoint | Route file | Role tối thiểu | Middleware hiện có | Cần thêm |
|---|---|---|---|---|
| `GET /users/with-status` (`GET_USERS_WITH_STATUS`) | `user.route.ts` | ADMIN | (không có) | `protectRoute`, `requireRole(ADMIN)` |
| `PUT /users/:id` (`UPDATE`) | `user.route.ts` | ADMIN | `protectRoute` | `requireRole(ADMIN)` |
| `PATCH /posts/:id/status` (`UPDATE_POST_STATUS`) | `post.route.ts` | ADMIN, MODERATOR | (không có) | `protectRoute`, `requireRole(ADMIN, MODERATOR)` |
| `PATCH /posts/:id/visibility` (`UPDATE_POST_VISIBILITY`) | `post.route.ts` | ADMIN, MODERATOR | (không có) | `protectRoute`, `requireRole(ADMIN, MODERATOR)` |
| `GET /reports` (`GET`) | `report.route.ts` | ADMIN, MODERATOR | (không có) | `protectRoute`, `requireRole(ADMIN, MODERATOR)` |
| `PATCH /reports/:id/response` (`RESPONSE`) | `report.route.ts` | ADMIN, MODERATOR | (không có) | `protectRoute`, `requireRole(ADMIN, MODERATOR)` |
| `PATCH /reports/:id/reject` (`REJECT`) | `report.route.ts` | ADMIN, MODERATOR | (không có) | `protectRoute`, `requireRole(ADMIN, MODERATOR)` |

## Scope Addendum (discovered during implementation)

`PUT /users/:id` hoá ra là endpoint DÙNG CHUNG cho tự-sửa-hồ-sơ (mọi user, gọi từ Breads-Fe) VÀ đổi status bởi admin (gọi từ Breads-Admin) — không phải endpoint admin-only thuần như giả định ban đầu. Áp thẳng `requireRole(ADMIN)` sẽ phá tính năng tự sửa hồ sơ của user thường. Đã mở rộng: thêm `requireSelfOrRole(ADMIN)` (cho qua nếu tự sửa hồ sơ mình HOẶC là Admin) dùng riêng cho endpoint này; đồng thời phát hiện và sửa 1 bug có sẵn trong `user.controller.ts` — check "chỉ sửa hồ sơ mình" cũ so sánh `req.params.id` với chính giá trị lấy từ `req.params.id`, không bao giờ chặn được gì (đã xác nhận với user trước khi mở rộng scope).

## Implementation Steps

1. Tạo `Breads-Be/src/api/middlewares/requireRole.ts`:
```ts
import HTTPStatus from "../../utils/httpStatus.js";

const requireRole = (...roles: number[]) => {
  return (req, res, next) => {
    if (!req.user || !roles.includes(req.user.role)) {
      return res.status(HTTPStatus.FORBIDDEN).json({ message: "Forbidden" });
    }
    next();
  };
};

export default requireRole;
```
(Kiểm tra `HTTPStatus` có sẵn giá trị `FORBIDDEN` — nếu chưa có, dùng số `403` trực tiếp, tham khảo cách `protectRoute.ts` dùng `HTTPStatus.UNAUTHORIZED`.)

2. Import `Constants` (từ `Breads-Shared`) trong 3 file router để lấy `Constants.USER_ROLE.ADMIN`/`MODERATOR`.

3. `user.route.ts`: thêm `protectRoute, requireRole(Constants.USER_ROLE.ADMIN)` vào route `GET_USERS_WITH_STATUS` (hiện chỉ có `validate(...)`); thêm `requireRole(Constants.USER_ROLE.ADMIN)` ngay sau `protectRoute` hiện có ở route `UPDATE` (`PUT /:id`).

4. `post.route.ts`: thêm `protectRoute, requireRole(Constants.USER_ROLE.ADMIN, Constants.USER_ROLE.MODERATOR)` vào 2 route `UPDATE_POST_STATUS` và `UPDATE_POST_VISIBILITY` (hiện chỉ có `validate(...)`).

5. `report.route.ts`: thêm `protectRoute, requireRole(Constants.USER_ROLE.ADMIN, Constants.USER_ROLE.MODERATOR)` vào route `GET` (`REPORT_PATH.GET`), và vào 2 route `RESPONSE`/`REJECT` (hiện chỉ có `validate(...)`).

6. **Trước khi thêm `protectRoute` vào 5 endpoint hiện chưa có nó:** kiểm tra `Breads-Admin` (userApi.ts/RTK Query các endpoint tương ứng khi được xây ở epic sau) và `Breads-Fe` hiện có đang gọi các endpoint này có kèm `Authorization` header hay không — nếu FE hiện tại (Fe's admin pages) gọi các endpoint này KHÔNG kèm token, thêm `protectRoute` sẽ phá luồng đó (plan-review Risk #5). Xác nhận trước khi merge.

7. Đặt `requireRole` LUÔN đứng SAU `protectRoute` trong mọi route đã sửa — thứ tự sai khiến `req.user` là `undefined` khi `requireRole` đọc `req.user.role`, gây crash 500 thay vì trả 403 đúng nghĩa.

## Acceptance Criteria

- **FR-5 / scenario:** GIVEN request tới 1 trong 7 endpoint với token hợp lệ nhưng role không nằm trong danh sách cho phép (vd: role USER gọi `PUT /users/:id`), WHEN request tới server, THEN nhận HTTP 403, không có thay đổi dữ liệu nào xảy ra.
- **FR-5 / scenario:** GIVEN request tới 1 trong 7 endpoint với token hợp lệ và role đủ quyền, WHEN request tới server, THEN hành vi nghiệp vụ y hệt trước khi thêm middleware (không đổi response shape/status code thành công).
- **FR-5 / scenario:** GIVEN request KHÔNG có token tới 1 trong 5 endpoint trước đây không yêu cầu đăng nhập, WHEN request tới server, THEN nhận 401 (từ `protectRoute`) trước khi tới `requireRole`.
- **NFR-2 / scenario:** GIVEN `protectRoute` chạy trước `requireRole` trong chain đã sửa, WHEN request hợp lệ đi qua, THEN side-effect `lastActiveAt` của `protectRoute` vẫn cập nhật đúng như trước (không bị `requireRole` chặn/bỏ qua).

## Technical Details

Tham chiếu `protectRoute.ts` hiện có (`Breads-Be/src/api/middlewares/protectRoute.ts`) để giữ đúng style file (import `HTTPStatus` từ `../../utils/httpStatus.js`, export default). `report.route.ts` hiện tại:
```ts
router.get(REPORT_PATH.GET, validate(getReportsSchema), asyncHandler(getReports));
router.post(REPORT_PATH.CREATE, protectRoute, validate(sendReportSchema), asyncHandler(sendReport));
router.patch(REPORT_PATH.RESPONSE, validate(responseReportSchema), asyncHandler(rejectReport));
router.patch(REPORT_PATH.REJECT, validate(rejectReportSchema), asyncHandler(rejectReport));
```
(Chỉ `CREATE` có `protectRoute`; `GET`/`RESPONSE`/`REJECT` hoàn toàn mở — đây chính là phần cần vá.)
