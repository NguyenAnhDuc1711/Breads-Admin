## Context

`LoginPage.tsx` hiện CHỈ chấp nhận role `ADMIN` (`if (result.role !== Constants.USER_ROLE.ADMIN) { logout(); return; }`) — nghĩa là sau khi role `MODERATOR` được thêm (task 001), tài khoản Moderator vẫn KHÔNG đăng nhập được vào `Breads-Admin`, phá vỡ toàn bộ mục tiêu của epic (Moderator là persona chính, số lượng đông). Đồng thời, `AdminLayout` (task 002) hiện chưa có bất kỳ kiểm tra quyền nào sau khi đăng nhập — 1 Moderator hợp lệ (hoặc tệ hơn, ai đó với token cũ) có thể gõ thẳng URL `/users` và vào được, dù không nên có quyền quản lý Users.

## Description

Sửa điều kiện đăng nhập ở `LoginPage.tsx` để chấp nhận cả `ADMIN` và `MODERATOR`. Thêm route-guard vào `AdminLayout` (đã tồn tại từ task 002) — đọc role qua `useGetCurrentUserQuery`, so với danh sách role-cho-phép khai báo theo route trong `src/config/routes.ts` (file mới), ẩn mục sidebar không đủ quyền, redirect `/login` khi truy cập route không đủ quyền. **Default-deny bắt buộc:** role không nằm trong danh sách cho phép — kể cả `undefined` hoặc giá trị không nhận diện — luôn bị coi là không đủ quyền.

## Implementation Steps

1. Tạo `src/config/routes.ts`:
   ```ts
   import { Constants } from "@/Breads-Shared/Constants";

   // Role-cho-phép theo route. Đây là khai báo RIÊNG ở FE (chỉ ảnh hưởng UI:
   // ẩn nav item / redirect sớm) — nguồn enforce THẬT là middleware requireRole
   // ở Breads-Be (xem PRD FR-5 bảng role-mapping, task 010). 2 nơi này không
   // tự động đồng bộ — cập nhật cả 2 khi thêm/đổi route quản trị mới.
   export const ROUTE_ROLES: Record<string, number[]> = {
     "/": [Constants.USER_ROLE.ADMIN, Constants.USER_ROLE.MODERATOR],
     "/posts": [Constants.USER_ROLE.ADMIN, Constants.USER_ROLE.MODERATOR],
     "/posts/validation": [Constants.USER_ROLE.ADMIN, Constants.USER_ROLE.MODERATOR],
     "/report": [Constants.USER_ROLE.ADMIN, Constants.USER_ROLE.MODERATOR],
     "/users": [Constants.USER_ROLE.ADMIN],
   };
   ```
2. Trong `AdminLayout.tsx` (từ task 002): thêm `useGetCurrentUserQuery()`, dùng `useLocation()` (react-router-dom) để lấy path hiện tại, tra `ROUTE_ROLES[pathname]`. Nếu đang `isLoading` → render `null`/spinner tạm, KHÔNG redirect (tránh flash-redirect trước khi có data — epic Risk #6). Nếu đã có data và `!allowedRoles?.includes(currentUser?.role)` (bao gồm case `currentUser` là `undefined`) → `<Navigate to="/login" replace/>`.
3. Sidebar: với mỗi mục nav, chỉ render nếu `ROUTE_ROLES[path]?.includes(currentUser?.role)` đúng — Moderator sẽ không thấy mục "Users".
4. Sửa `src/pages/LoginPage.tsx`: đổi điều kiện
   ```ts
   if (result.role !== Constants.USER_ROLE.ADMIN) {
   ```
   thành
   ```ts
   const allowedLoginRoles = [Constants.USER_ROLE.ADMIN, Constants.USER_ROLE.MODERATOR];
   if (!allowedLoginRoles.includes(result.role)) {
   ```
   (dùng danh sách tường minh, KHÔNG dùng phép so sánh `!==` đơn — sai sót ở đây sẽ mở đăng nhập cho role USER thường, đúng lỗ hổng epic đang vá — xem epic Risk #3).

## Acceptance Criteria

- **FR-8 / scenario:** GIVEN tài khoản role Moderator, WHEN đăng nhập ở `/login` với email/password đúng, THEN đăng nhập thành công, điều hướng vào Breads-Admin (không bị `logout()` + báo lỗi như trước).
- **FR-8 / scenario:** GIVEN tài khoản role USER (thường), WHEN đăng nhập ở `/login`, THEN vẫn bị từ chối như hành vi cũ (không có regression mở quyền).
- **FR-6 / scenario:** GIVEN đăng nhập với role Moderator, WHEN xem sidebar, THEN mục "Users" không hiển thị.
- **FR-6 / scenario:** GIVEN đăng nhập với role Moderator, WHEN truy cập trực tiếp URL `/users`, THEN bị điều hướng về `/login` (không thấy nội dung trang Users).
- **FR-6 / scenario:** GIVEN đăng nhập với role Admin, WHEN truy cập bất kỳ route nào trong 5 route, THEN vào được bình thường, sidebar hiện đủ 5 mục.
- **FR-6 / scenario (default-deny):** GIVEN `currentUser.role` là giá trị không nằm trong `{ADMIN, MODERATOR}` hoặc `undefined` (dữ liệu bất thường), WHEN vào bất kỳ route quản trị nào, THEN bị điều hướng `/login` — không được ngầm định cho qua.
- **FR-6 / scenario (loading):** GIVEN `useGetCurrentUserQuery` đang loading, WHEN `AdminLayout` render lần đầu, THEN KHÔNG redirect `/login` ngay (chờ data trước).

## Technical Details

```tsx
const result = await login({ email, password }).unwrap();
if (result.role !== Constants.USER_ROLE.ADMIN) {
  await logout();
  setError("Tài khoản này không có quyền truy cập trang quản trị.");
  return;
}
```
